Works at project level.

  • Project metadata only, with one schema per project, up to 30 fields and up to 20 options per dropdown.
  • Project administrators can change definitions and values; users with Browse Projects can read all fields. There is no field-level restricted visibility.

  • Jira Cloud is the target platform. No Jira Data Center edition is available.

Privacy & data

ProjectKit stores each project's field definitions, entered values, current revision and last-save time in Atlassian Forge storage, scoped to the app installation. Names, links and free text can contain personal information. The app does not keep a history of earlier content.

Project administrators can explicitly link known Atlassian accounts to people identified in their project content. ProjectKit stores those account IDs, their first verified attribution time, project references and privacy-reporting state. It does not infer identity from a name or assume the editor is everyone mentioned. Names returned by Jira people search are displayed without storing profile copies.

Everyone with Browse Projects can read the project's full ProjectKit form. Editing and removal require both Browse Projects and Administer Projects. People search also follows Jira directory permissions. There is no field-level restricted visibility: keep credentials and information requiring narrower access outside ProjectKit.

The app uses Jira project-permission, user-directory, Forge storage and personal-data-reporting permissions. It does not retrieve Jira issues or attachments and has no external app backend, AI processing, advertising or app analytics. Publisher diagnostics exclude entered values and personal account identifiers. Website analytics and support email are separate from app storage.

An hourly worker reports explicitly linked accounts to Atlassian's Personal Data Reporting API, following the reporting interval supplied by Atlassian or its seven-day default. Pending or overdue checks block fresh access to affected content until resolved. Retries and outages can delay processing; this is not a deletion-time guarantee.

Whole-project removal: when Atlassian instructs the app to erase or refresh a linked account, ProjectKit permanently clears every ProjectKit field, value and account link in each associated project workspace, including unrelated content. There is no undo. Jira projects, issues and other apps are unaffected. The app warns before a new account is linked. Existing links cannot simply be detached while retaining the content.

Project admins can manually correct fields or clear all ProjectKit data after confirmation, including after licence expiry. Names and details in unlinked free text are not automatically identified or erased: customers must use their own privacy-request process and manual correction/removal. Previously viewed information and downloaded CSV files cannot be remotely removed. Uninstall and backup retention follow Atlassian's Forge storage lifecycle.

Account attribution supports up to 90 linked accounts and 100 linked projects per installation, subject to a 160 KB registry limit. Removal is processed in batches of up to eight project workspaces per worker run; affected access stays blocked while the queue is processed. Unsupported reporting intervals pause access for support review.

For a privacy or deletion request, email apifymcpfactory@gmail.com. Describe the project and field using non-sensitive references. Do not send passwords, tokens or private project content.

Browser demo: the interactive sample uses fictional data held only in the current page’s memory. Changes reset on refresh. It makes no Jira requests and does not save to Jira or Forge storage.

Does it replace Jira custom fields?

No. ProjectKit is for metadata attached to a project. It does not create or replace fields on Jira issues.
