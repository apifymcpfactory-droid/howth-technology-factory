API Contract Workbench | HTF

Privacy and data handling

Adopted 11 November 2026

Who to contact

Fred Jones, trading as HTF, is the controller for product support correspondence. Email support@howthtechnologyfactory.pro for privacy questions or requests. This notice does not replace your organisation's policies for the APIs and data you choose to use.

Work in your IDE and project environment

The plugin reads local files you select, such as API contracts, collections, environments, request definitions, schemas, descriptor sets and GraphQL request files. Editors and result previews can contain request and response contents, queries, variables, scripts and diagnostic paths. That material may include personal or confidential data supplied by you.

Contract review and local schema validation do not send files to an HTF backend. The plugin has no HTF-hosted API processing service, AI processing service or built-in usage analytics. It does not upload your project or API results to HTF automatically. IDE reporting, remote development, file sync and backup services are controlled separately by your environment.

Network requests you choose

Explicit HTTP, GraphQL and gRPC operations send the selected request and applicable authentication to the target you choose. Explicit gRPC reflection requests service descriptions from that endpoint. Explicit OAuth client credential acquisition sends the configured client information to the chosen token endpoint. Those services may receive your network address, headers, metadata, bodies and credentials and apply their own retention and privacy rules.

Importing a collection or opening a saved run does not replay an API operation. Collection scripts are retained as source data and are not run automatically. A reviewed JavaScript assertion can run in a separate local JVM. Its restricted runtime is not an operating-system sandbox. Run only trusted scripts.

Local storage

Named environments and authentication profiles are project files under .htf-api-workbench. They can include targets, variable values, usernames or client IDs and credential slot names. They are not encrypted secret files. Request definitions and original exports are saved at locations you choose and may retain literal credentials already present in source content. The plugin does not promise complete secret detection or automatic redaction.

Credential values, cached OAuth tokens and the project authentication revision key use the IDE credential-store API. Your configured IDE provider and environment govern their storage. HTF does not operate that store. Token acquisition is explicit and the plugin does not automatically fetch or refresh tokens.

Saved run evidence contains outcomes, status, timing, identifiers, timestamps, assertions and revision or response hashes. It is designed to omit raw response bodies, request headers, scripts, environment values and licence proofs. Hashes are identifiers, not a guarantee of anonymity. Review every file or screenshot before sharing it.

There is no automatic retention expiry or promise that uninstalling the plugin removes project files, backups or credential entries. Remove files you no longer need. Clearing a cached token locally does not revoke it at its server. HTF cannot remotely inspect or erase your local project or IDE store.

Marketplace licensing

The plugin reads the product confirmation stamp from the IDE and verifies supported proofs in memory. It does not send contract or API contents to HTF for licensing and does not operate a separate HTF licence server. JetBrains handles Marketplace account, order and licence communication under its privacy terms.

Support correspondence

When you email support, HTF receives the details you send, your email address and normal message metadata. The support address forwards to a central Google mailbox, so external mail and forwarding services handle delivery and hosting. Do not send passwords, access tokens, private keys, activation codes, identity documents or unreviewed production data.

HTF uses correspondence to respond, investigate the issue and administer the product. Marketplace customer and order information made available to HTF is used for product support and required administration. The plugin does not collect payment card details.

Correspondence is retained while needed for the request, related support history or applicable record and claim obligations, then deleted when no longer needed for those purposes. There is no configured automatic deletion interval. Access is limited to the people and service providers handling those purposes.

Your choices and rights

Send only the minimum information needed. You may ask HTF about access, correction, deletion, restriction, objection or portability of information HTF holds where those rights apply. These requests cannot reach into your device or reverse processing by a third-party endpoint. You may also contact the data protection authority responsible for your location. Website visits have a separate privacy notice.
