Give the next person more than a recording.

Your editor needs to know which moments matter. The next operator needs to know what went wrong and how you fixed it. Keep those notes with the production checklist, then share a report instead of asking someone to piece together separate messages or rely on your memory.

Check OBS before logging the session

Run Preflight checks the OBS connection and whether it reports recording or streaming. A failed check blocks the session record from starting, so a connection problem is visible before you continue.

Record the details people will ask for

Advance your checklist and add notes with timestamps as important moments happen. Record a problem and the steps you took to resolve it, so the person reading the report has the context.

Share notes in a useful format

Use the readable Markdown report for people, CSV event rows for a spreadsheet, or JSON for a technical workflow. Keep the exported files with the rest of the production.

Plan the work. Record what happens. Share the notes.

In Stream Deck settings, name the session, enter a production checklist (called a rundown in the plugin) and set the notes attached to your buttons. Start and stop recording separately in OBS.

  1. Set the checklist

    Configure the OBS connection, session title and production steps. Run Preflight, review its result and check the microphone signal and recording destination yourself.

  2. Add notes as you work

    Start the session record. Move through the checklist, timestamp important moments and log problems. After resolving a problem yourself, record what you did and confirm it.

  3. Export the session report

    Press Stop Session twice within five seconds to complete the record. Save the report files before starting a new session, ready for your editor or next operator.

Recording stays under your control. Start Session and Stop Session manage the production record. They do not start or stop OBS recording or streaming. Audio Health reads mute and volume settings; it does not listen for sound or certify that audio is present.

Questions before you choose it.

Compatibility, setup, data and what is included.

What does Production Operations Suite do?

It provides twelve Stream Deck actions to check local OBS when pressed, follow a production checklist, keep dated notes and record problems with their resolutions. Create Handoff exports a session report for the next operator or editor as JSON, Markdown and CSV files.

Who is it for?

It is for Windows-based OBS operators, stream producers and small production teams that want a repeatable operating workflow on Stream Deck.

Does it control OBS over the internet?

No. Release 0.1 accepts only localhost OBS WebSocket addresses on the same computer and reads OBS status; Start/Stop do not control OBS outputs.

Do Start Session and Stop Session start or stop my OBS recording?

No. They start and complete the local production record. Operate recording and streaming separately in OBS.

Where do I name the session and configure the rundown?

Select Run Preflight in Stream Deck. Set the session title and enter one rundown step per line; the rundown is your production checklist. Save it, then advance the steps as you work. Blank fields use a default title and four default steps; custom rundowns support 1–50 steps.

What does preflight actually check?

It verifies the configured local OBS connection and obtains OBS version, recording status and streaming status. It does not inspect microphone signal, disk space or recording destination capacity; those remain operator checks.

Does it require a Howth Technology Factory account or cloud service?

No. There is no Howth Technology Factory account, backend, analytics or telemetry in the release candidate.

Which Stream Deck software version is required?

Stream Deck 7.1 or later.

Which operating systems are supported?

Release 0.1 supports Windows 10 or later. macOS is not claimed in this release.

Which OBS version is required?

Use an OBS Studio version with OBS WebSocket v5 available and enabled.

Where do I enter the OBS WebSocket password?

Select Run Preflight, Production Health or Audio Health and enter it in that action's local property inspector. Settings are configured separately for each action.

Is the OBS password sent to Howth Technology Factory?

No. It remains in Stream Deck settings and the plugin excludes it from logs.

What happens if OBS is unavailable?

The next health or preflight check reports unavailable. These checks run when pressed, so a previously displayed title is not continuous monitoring.

Does Audio Health prove that sound is being captured?

No. It reports the configured OBS input's mute and volume settings; it deliberately does not claim live signal detection.

How does guarded stopping work?

Stop Session requires a second press within five seconds. A single press expires without completing the local record. OBS recording and streaming are unaffected.

What can I mark during a session?

Add Marker records the date and time, a configured label and an optional note in the session record. It does not insert a marker into a video file or calculate a position within footage. Set the label and note before pressing the key; update them before subsequent presses when the details change.

What happens when I capture an incident?

The configured summary and note are recorded with a timestamp, and the local session enters a recovery-required state. Address the issue yourself, then enter and save a recovery result before pressing Run Recovery Step. The action records your confirmation and returns a started session to running, or a prepared session to ready. It does not repair equipment or control OBS.

What files does Create Handoff produce?

It writes three files to a new local folder after completion: JSON with session data, markers, incidents, rundown status and audit events; Markdown with a readable session/marker/incident summary; and CSV with timestamped marker and incident rows. The formats contain different views of the session, not identical copies of every field.

Can I keep several active sessions?

Release 0.1 retains one active session record. Export a completed session before running preflight to prepare the next; preparing it replaces the previous active record.

Where can I save a handoff, and is it encrypted?

Choose an existing folder on a local Windows drive using an absolute path. UNC shares and device paths are refused. Exports are not encrypted by the plugin and inherit the destination folder's Windows permissions; choose the folder and sharing permissions appropriately. Wait for REPORT / SAVED before using the three files.

What if a saved session cannot be restored?

The plugin reports BACKUP / INVALID and refuses to treat the record as valid. If you decide to discard that unreadable session, Run Preflight provides an explicit RESET SESSION confirmation. This starts fresh and cannot recover the discarded data. Previously exported handoffs are separate files.

Can I create a handoff before stopping the session?

No. Incomplete sessions are refused.

Does the plugin upload recordings or handoff files?

No. It does not upload recordings or handoff bundles.

Can I open my own runbook or dashboard?

Yes. Configure an explicit URL on Open Dashboard or Runbook.

Does this replace OBS backup recording or a disaster-recovery plan?

No. It supports the operating workflow but does not replace a tested production recovery plan.

Where can I get help?

Use the support contact shown in the marketplace listing and include the Stream Deck version, Windows version, OBS version and the action that failed. Never send your OBS password.
