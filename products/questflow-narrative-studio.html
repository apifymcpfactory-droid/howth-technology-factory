Product guide

Use QuestFlow when a writer needs to author a branch, a designer needs to play both routes, and a programmer needs stable identifiers for gameplay and saves. QuestFlow runs inside Unreal Engine. The included story, The last ferry, lets the player light two harbour lamps or guide the ferry directly.

Play the included story

  1. Enable QuestFlow Narrative Studio in Edit → Plugins and restart Unreal Editor if prompted. For a source distribution, place the plugin folder containing QuestFlowStudio.uplugin inside your C++ project's Plugins folder, then build its Development Editor target with the UE 5.8 Windows C++ toolchain.
  2. Turn on Show Plugin Content in the Content Browser settings. In the QuestFlow plugin's Examples folder, open L_HarbourWatch.
  3. Select one player and Play Standalone as the play net mode, then press Play. Continue past the harbour keeper's opening line. Keep a rehearsal checkpoint at the fork, choose Light the lamps, and record two objective events to see the ending. Return to the checkpoint and try Guide the ferry.
  4. End play. Open NS_HarbourWatch to see where the routes separate and meet again. The checkpoint lasts for that play session. The sample does not write to a player's disk slot.

Author your own story

Create a QuestFlow Story in the Content Browser. Its starting graph already contains a conversation, a decision, an objective and an ending. Select a node to edit its text and options. Drag an output pin to the next node's input. Set start selects the entry node. Validate checks for missing text, unattached outputs, unreachable nodes, duplicate IDs and circular paths. Correct the reported node, validate again and save the asset.

Add a QuestFlow Story Rehearsal actor to a dedicated test level and assign your graph to its Story field to play your changes. Keep one rehearsal actor in that level. It supplies a standalone preview interface. Your production game can present the same story through its own UI.

For a spreadsheet-led team, use Import / export → Create Data Table. Each named row represents a node. One row marks the start. Continuations, failure paths and keyed choices refer to row names. Use Apply Data Table to bring edits back into the story. Validate your edited table before replacing a published story. An invalid import reports the problem and retains the existing graph. During Play in Editor, the graph's live inspector can follow an active player component for that graph.

Connect a game

Add a Quest Flow Narrative Player Component to the actor that owns the story. Call Start Narrative on the authority with your graph. Read Get Active Node and Get Playback to display the current content. Listen for On Narrative Changed to refresh the interface when state changes.

To show the included gameplay HUD, use Create Widget with the QuestFlow Quest Tracker class and your local player controller. Call Bind Quest Tracker with that player's narrative component, then Add to Player Screen. The tracker shows the current story, objective counts and ending. You can pass your Unreal String Table when binding. If the local player changes characters, bind the new character's component. Bind an empty component to clear the tracker.

When the player acts Call on the authority
Continues a spoken line Advance Dialogue with the displayed node ID
Selects an option Select Choice with the node and choice IDs
Completes an objective action Apply Objective Progress with the node ID, objective ID and positive event count
Triggers an authored failure condition Fail Objective with the active node ID. Connect the failure route when authoring that objective.

Use Parallel Objectives when events can arrive in any order. Give each requirement a stable ID and target. Read each one with Get Condition Progress. The successful route opens after all targets are met. To issue a gameplay reward, set Reward ID on the objective and bind the server's On Reward Earned event. Your game decides what the reward does. If it writes to a separate inventory or service, persist the supplied playthrough ID and reward ID together to prevent a repeated grant. Restoring a checkpoint does not grant the reward again.

Check the returned success flag and error text. Passing the displayed node ID prevents a delayed click from acting on the next node. For multiplayer, use a replicated owning actor. Its relevancy determines which clients see the story state. Route each player's input through your game's normal server-side checks. The rehearsal actor is for standalone play.

Preserve an existing player's progress

Call Create Snapshot on the authority and write its result with Unreal's Save Game to Slot. Your game chooses the player, slot name and storage policy. After Load Game from Slot, cast the result to Quest Flow Narrative Save Game and call Restore Narrative. Check that it succeeded before replacing an older slot.

Text edits can keep their original node and choice IDs. When publishing a structural revision, increment the graph's Definition Version. Create a Data Asset of class Quest Flow Save Migration. Choose the destination graph, pin its version and add a source-version mapping for each older revision you support. Keep surviving IDs unchanged. Fill in replacements for nodes or choices that have moved to new IDs. A choice replacement uses its original node and choice IDs.

Call Restore Migrated Narrative with the player's existing save. QuestFlow checks that the mapped choice history can reach the saved objective and that the original progress still fits. A failed restore leaves the source save and running state available for recovery. After success, call Create Snapshot again and persist the new version using your normal save policy.

Keep reward IDs and the IDs of saved parallel conditions stable across a migration. The current playthrough cannot rewind to a snapshot that would remove an already earned reward. Use a fresh playthrough to rehearse a different reward history.

Review changes and translate dialogue

Export JSON writes the graph IDs, entry point, branch targets, source text, objective counts and layout. Nodes have stable ordering, so moving an asset or reordering its stored node array does not introduce unrelated changes into a code review. Option order stays in the writer's chosen display order. The JSON supports review and external tools. Author changes in the native graph.

Export string table writes an Unreal String Table CSV. Import it into a String Table asset, then use Get Localized Title, Get Localized Node Text and Get Localized Choice Label with that table. Your project handles translated cultures through Unreal's localisation tools. Missing entries fall back to the authored line. Assigning the table to the example actor's String Table field lets you rehearse the same lookup.

Choose Printable narrative review to share a local HTML handout with someone who does not run Unreal. Open it in a browser and follow a choice link to its destination. Use the browser's Print command to create a paper copy or PDF.

Compatibility, privacy and support

The plugin targets Windows 64-bit and Unreal Engine 5.8. The editable examples live in the plugin's Content/Examples directory. Exported files go to the location you select. QuestFlow includes no hosted account, analytics or separate service. The game controls normal Unreal replication and save storage.

For a linear objective checklist, follow the companion Harbour Beacon quick start. For help, include your Unreal version, the action you took and any validation message. Contact Howth Technology Factory

Play The Harbour Beacon

Open QuestFlow Studio Content → Examples → DA_HarbourBeacon in the Unreal Content Browser. Enable Show Plugin Content in the browser settings if the plugin folder is hidden. This quest asks the player to recover two lenses and light a beacon.

  1. In an Actor or Player Controller Blueprint, use Construct Object from Class with Quest Flow Session. Store its return value in a variable on the owning object.
  2. Call Start Quest with DA_HarbourBeacon. Check the returned success flag. On a failure, display Out Error. Use Get Active Objective to read the current description and target and Get Active Progress for the current count.
  3. On each collected lens, call Apply Progress with objective ID CollectLenses and amount 1. The second lens opens LightBeacon. Pass LightBeacon and 1 when the player lights it. Is Complete now returns true.

Save halfway through

After the first lens, call Create Save and pass the returned object to Unreal's Save Game to Slot using a slot and user index chosen by your game. Check that the write succeeded. To resume, load the same slot with Load Game from Slot, cast the result to Quest Flow Save Game, construct a session and call Restore Quest with the definition and loaded save. The next objective is still CollectLenses, at one of two.

For a new quest, create a Data Asset of class Quest Flow Definition. Give the quest and each objective permanent IDs, a player-facing description and a positive target count. Keep the IDs when polishing the text. Increment Definition Version when changing the sequence, IDs or counts. This version accepts matching save and definition versions. If a restore fails, report the returned error and preserve the player's slot.

Questions from game teams

Who would use this on a game team?

A writer can shape dialogue and choices, a quest designer can play the routes, and a gameplay programmer can connect the results to a game. A reviewer can read the exported story without running the project.

What should I try in the first five minutes?

Open the Harbour Watch example level in standalone play. At the ferry decision, keep a rehearsal checkpoint. Take the lamp route, return to the checkpoint and guide the ferry directly. Both routes arrive at the same ending through different actions.

Which Unreal setup is this for?

The target is Unreal Engine 5.8 on Windows 64-bit. The included source setup uses the matching Windows C++ toolchain. The linear quest example has run in a 5.8.4 Development Editor host.

Where do I find the examples?

Enable the plugin and turn on Show Plugin Content in the Content Browser. Open the QuestFlow Examples folder. Harbour Watch is the branching rehearsal. Harbour Beacon demonstrates a linear sequence. The two examples serve different purposes.

Can I start with something playable?

Choose QuestFlow Story under Gameplay in the Content Browser. The starter includes a spoken line, a two-way decision, a counted objective and a common ending. Replace the text and reconnect the routes as you write.

Can two choices lead back to the same scene?

Yes. Connect both paths to the input on the shared node. One route can pass through an objective while another reaches that same scene immediately.

Can players loop back to an earlier node?

Each QuestFlow story uses forward paths that reach endings. The editor rejects connections that create a cycle. During rehearsal, you can return to your checkpoint to explore an earlier decision.

What does the writer put in a Data Table?

Use QuestFlow Story Table Row. Give each row a name, designate one start and enter the dialogue or objective text. Use destination row names to connect the routes. Give each option a stable key so you can edit its wording or reorder the choices.

What happens if a writer misspells a destination?

Applying the Data Table reports the row and the missing destination. Fix the name in the table and apply it again. QuestFlow replaces the existing story only after the candidate rows validate and you confirm the change.

Can the graph become a table later?

Import / export → Create Data Table makes an editable Unreal asset with the node and choice identities. The asset can be edited in Unreal's table editor and applied back to the story.

What makes a quest objective complete?

Your game sends progress with the active node ID, the objective ID and a positive amount. The objective records progress toward the count set by the author.

Can a task require two different things?

Give an objective a primary requirement, then add parallel requirements with their own IDs and counts. For example, a quest can require a lens and lamp oil. Your gameplay code reports progress against the relevant ID.

What determines whether a player fails an objective?

Your game decides when an objective fails. An authored failure connection supplies the next story node. This lets the writer show what happens after failure while the game controls rules such as a time limit.

Does a reward create an item in my inventory?

Pair the objective with a reward ID and listen for the reward event. Your game maps that ID to an inventory change, achievement or other effect and decides how to persist it.

How can I tell which node is actually running?

Open the story during Play In Editor. The live bar identifies the running instance and its current text. Find active node moves the canvas to it. Next player switches between active instances of this story when more than one is present.

Do I need to build a dialogue screen to test a story?

The standalone rehearsal actor provides the sample controls. Place one in a dedicated test level and assign your story. In a production game, read the narrative component from your own interface.

Will a rehearsal checkpoint survive closing the level?

It lasts for the current play session. To keep a player's production progress across sessions, create a narrative snapshot and save it using Unreal's Save Game to Slot. Your game chooses the slot and when to write.

What happens to a save if I change the dialogue?

Keep graph, node and choice IDs stable when changing wording. When publishing a structural revision, version the definition and test existing saves against it. A migration asset can map replaced nodes and choices to a specified new revision and validate the restored route.

How do I use this from Blueprint or C++?

Add the narrative player component to the actor that owns the story. Start the graph, read its active node and send the displayed node ID when the player acts. Your game handles the success value and error text for each call.

Can a networked game use the story state?

The component is designed for an authoritative, replicated owning actor. The game validates player requests and Unreal actor relevancy governs which clients receive playback. The included rehearsal runs in standalone mode.

What do I send to a reviewer who has no Unreal installation?

Export Printable narrative review. The local HTML document contains the story text and route links. Open it in a browser to read it or use the browser's print command.

What does a localisation team receive?

Export the translation String Table CSV. It carries keys and authored text into Unreal's String Table workflow. Your team supplies and manages translations. Missing entries fall back to the authored text.

Can another tool read the story structure?

Export story JSON for structured nodes, choices and connections. For editable rows that you plan to bring back into QuestFlow, use the Unreal Data Table workflow.

Where are my scripts, exports and player saves stored?

The story is an Unreal project asset. You choose where to save each export. Your game controls player storage and network replication. The plugin integration uses the engine without requiring a QuestFlow cloud account.

Is there a simpler example for a linear mission?

In Harbour Beacon, recover one lens, restore the partial count in a fresh session, then recover the second and complete the beacon objective. A separate native save-slot test preserved both completed objective IDs and partial progress. Harbour Beacon guide

Where can I get help with a story that fails validation?

Include your Unreal version, the node or table row you were editing, the action you took and the exact message. Reproduce the issue with example text if your game is confidential. Contact Howth Technology Factory
