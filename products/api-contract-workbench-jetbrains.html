Keep the next change understandable.

API changes can leave tests and release notes out of step. The intended workflow connects the contract, the checks you review and the evidence you keep, with accessible annual pricing.

Review the contract

The development engine reads OpenAPI JSON and YAML and highlights selected changes, including removed operations and new required inputs.

Prepare repeatable checks

Generate a draft suite from a contract or import supported Postman requests. Draft cases stay disabled until reviewed. Run explicit HTTP checks against an environment you choose.

Keep useful evidence

Save a local result record with input revisions, outcomes and response hashes. Input changes mark the current result as stale so it can be rerun.

A working foundation, with release testing ahead.

The core contract, HTTP, scripting and evidence engines have automated tests. A native IntelliJ development build is being tested. The product has not been submitted for review.

  • Contract checks cover selected changes, not every OpenAPI compatibility rule. Imported requests need manual review. Postman scripts are retained as source data rather than executed automatically.
  • Broader collection support, authentication workflows, gRPC, reusable environments, result comparison and team release workflows are planned. Availability will follow integration and testing.
  • Native usability, compatibility, credential handling, licensing, dependency review and production acceptance remain release gates. Final scope and pricing will be confirmed before launch.
Data and requests

The current development build processes contract and suite files locally. An explicit test run sends requests to the origin you choose. It has no HTF cloud backend or AI processing. Local evidence stores outcomes and response hashes, not response bodies or request headers.

Credential handling and the final data disclosure still require native verification. This page follows the website privacy notice.
